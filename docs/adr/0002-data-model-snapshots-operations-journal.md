# ADR 0002. Модель данных: Program, Snapshot, Operation, журнал, undo/redo

Статус: предложено (этап 0) · 2026-11-07 · Architect

## Контекст

Требования дизайна: UI «никогда не ждёт анализ» и читает модель через снимки; изменения — только операциями, они идут в журнал и undo; журнал — единственный источник правды, анализ — пересчитываемый кэш; проект — один SQLite-файл; undo глобальный и в пределах функции. Анализ параллельный (rayon) и публикует результаты постепенно. Бинари — до сотен МБ, функций — до сотен тысяч.

## Решение

### Слои

```
Program (Arc, неизменяем с момента загрузки)
  LoadedImage: BinaryInfo, MemoryMap (исходные байты), сегменты, секции, символы, импорты, релокации, FunctionHint
  Arc<dyn Arch> + индексы (адрес → лучший символ, PLT → импорт)
UserState (персистентные мапы imbl; производное от журнала)
  names, types, comments, definitions (code/data), function overrides (create/delete), bookmarks, tags,
  memory = MemoryMap с оверлеем патчей
AnalysisResults (персистентные мапы imbl; кэш)
  functions, block-индекс, xref-группы + индексы to/from, strings, progress
Snapshot = { generation, Arc<Program>, Arc<UserState>, Arc<AnalysisResults>, UndoInfo }
```

`Snapshot` — конкретная структура, а не трейт: реализация одна, мок строится той же структурой из синтетической `Program`. Клонирование — четыре `Arc`.

### Публикация снимков: `arc-swap` + персистентные структуры

- `SnapshotHub` хранит `ArcSwap<Snapshot>`. Читатели: `hub.load() -> Arc<Snapshot>` — **без блокировок**, безопасно в UI-потоке.
- Писатели (сессия при операции, драйвер анализа при слиянии результатов) вызывают `hub.update(|old| new)` / `hub.update_analysis(|results| ...)` — замыкание выполняется под коротким мьютексом писателей и получает *текущий* снимок (сериализует писателей, читатели его не видят), `generation += 1`, затем уведомляют подписчиков `SnapshotListener::snapshot_published(generation)` в потоке публикации.
- Внутри снимка большие коллекции — `imbl::OrdMap` (B-дерево со structural sharing): новая версия после правки одной функции — O(log n) памяти и времени, старые снимки, которые держит UI, остаются валидными. Драйвер анализа обязан троттлить публикацию (≈ 5–10 раз/с при массовом анализе).
- Наружу `imbl` не торчит: доступ через методы (`functions()`, `function_containing()`, `xrefs_to()`...). Замена структуры не ломает API.

### Операции

`enum Operation` (`#[non_exhaustive]`, serde-тег `"op"`): `Rename`, `SetType`, `Comment`, `DefineCode`, `DefineData`, `Undefine`, `CreateFunction`, `DeleteFunction`, `ResetFunction`, `PatchBytes`, `Bookmark`, `AddTag`, `RemoveTag`, `Batch`. Поля `Option<_>` со значением `None` означают «снять/вернуть к автоматическому». Все десять операций из дизайна покрыты; `Undefine`, `ResetFunction`, `RemoveTag` добавлены, чтобы любая операция имела обратную **в том же языке операций**; `Batch` — составная операция как один шаг undo.

- `Operation::validate()` — проверка аргументов (пустые/слишком длинные имена, пробелы и управляющие символы в имени, патч вне отображённой памяти, лимиты размеров).
- `UserState::apply(&op) -> Result<Operation /* inverse */>` — применяет и возвращает точную обратную операцию (rename хранит прежнее имя, патч — прежние байты). При ошибке состояние не меняется (`Batch` применяется к копии).
- `Operation::changes() -> Vec<Change{kind, range}>` — что затронуто (`Name`, `Type`, `Comment`, `Annotation`, `Definition`, `Function`, `Bytes`). Используется для инвалидации анализа (ADR 0003) и для конфликтов undo. `Name/Comment/Annotation` не трогают анализ — переименование мгновенно и не перезапускает проходы.
- JSON-форма операции — формат хранения в проекте, поэтому варианты и поля можно только **добавлять**; адреса в JSON — строки `"0x401000"`.

### Журнал и undo/redo

- `Journal` (чистая логика в `dasm-core`) = список `JournalEntry { seq, op, inverse, meta: OpMeta{author, timestamp_ms, source}, scope: Option<function entry>, state: Active|Undone|Discarded }` + текущий `UserState` + стек redo.
- `apply` → новый Active-элемент, весь стек redo становится `Discarded` (история сохраняется, но не повторяется). `undo(scope)` применяет `inverse` последнего Active-элемента в области, `redo(scope)` — заново применяет `op` (обратная пересчитывается).
- **Undo в пределах функции** (`UndoScope::Function(entry)`): берётся последний Active-элемент с этим `scope`; если позже есть Active-элемент, затрагивающий тот же объект (`Change::conflicts_with`), — `Error::UndoConflict`, состояние не меняется. `scope` проставляет `Session` по `function_containing(op.primary_address())`.
- Каждая мутация возвращает `JournalEvent`ы (`Appended`, `StateChanged`), которые `ProjectStore::record` пишет **атомарно**. `Session` сначала применяет к копии журнала, затем пишет в store, и только после успеха подменяет журнал и публикует снимок — то, что видит UI, уже на диске.
- Восстановление: `Journal::replay(UserState::new(image.memory), store.load_journal())` применяет Active-элементы по `seq`; Undone образуют стек redo (redo переживает перезапуск). Если Active-элемент больше не применяется — проект повреждён, `Error::Store`.

### «Журнал — источник правды, анализ — кэш»

- В проекте хранятся: исходные байты + SHA-256 + параметры загрузки (база PIE!), журнал, настройки. Результаты анализа **не** являются источником правды: при открытии они пересчитываются (кэширование результатов в SQLite — оптимизация, может появиться позже как `analysis_cache` с ключом `(sha256, journal_seq, версия анализатора)`).
- Все адреса в журнале абсолютные для базы, сохранённой в проекте. **Решение заказчика:** на этапе 1 база фиксируется при создании проекта; rebase — позже отдельной операцией (бэклог). `Session::open` отказывает (`Error::ProjectMismatch`), если база или SHA-256 не совпадают с сохранёнными.
- **Исходный файл** (решение заказчика): по умолчанию копия внутри проекта (`SourceContent::Embedded`); опционально «только ссылка» (`SourceContent::Linked { path }` + SHA-256). `StoredSource::read_bytes` читает ссылку с диска и сверяет SHA-256. `ProjectStore` обязан сохранять оба режима.
- **Версия формата журнала** `JOURNAL_FORMAT_VERSION` записывается при создании проекта; более новый проект — `Error::NewerProjectFormat` (не путать с повреждением, `Error::Store`). `LoadOptions` читается с serde-дефолтами. **Лимиты загрузчика (`Limits`) в проекте не хранятся** (`#[serde(skip)]`): файл проекта недоверенный, и подложенный проект не должен снимать лимиты; они всегда берутся из сборки или задаются вызывающим. `StoredSource::read_bytes` для ссылки тоже использует лимит сборки.
- **Автор операций** (решение заказчика): по умолчанию `$USER`, переопределяется настройкой. Настройка живёт в **профиле пользователя** (`$XDG_CONFIG_HOME/dasm/config.toml`, `[user] name`), а не в проекте: имя принадлежит человеку, а не файлу, и общий проект не должен навязывать одно имя всем. Разрешение — `dasm_core::resolve_author(configured)`: настройка > `$USER` > `$LOGNAME` > `"unknown"`; результат передаётся в `Session::open`.

### Листинг по адресу, а не по номеру строки

`Snapshot::item_containing(addr)` (элемент, покрывающий адрес, — выравнивание при переходе в середину инструкции), `listing_from(addr)` и `listing_before(addr)` (прокрутка вниз и вверх) лениво выдают элементы (инструкция, строка, данные, неизвестный байт), перепрыгивая через дыры в адресном пространстве. Текст строится только для видимых строк (`Snapshot::render_insn` → `Arch::render` с текущими именами). Анализ хранит только `insn_lens` в блоках, не текст. UI виртуализирует скролл по адресам (полоса прокрутки ≈ позиция в адресном пространстве), а не по числу строк — не нужно пересчитывать миллионы строк после каждого прохода.

### Текст из недоверенных источников (SEC-CORE-09)

Имена символов, комментарии и пути из файла могут содержать ANSI-escape и управляющие символы Unicode, меняющие вид текста. Политика (`dasm_core::text`):

| Что | Правило |
|---|---|
| Имена, теги, типы, автор, id плагина | Запрещены управляющие и все невидимые символы: категория Cf, разделители строк и абзацев, остальные default-ignorable (`text::is_invisible_char`). В именах также запрещены пробелы |
| Комментарии, заметки закладок | Разрешены `\n`, `\t` и символы формирования текста: joiners (ZWNJ/ZWJ), directional marks (LRM/RLM/ALM), variation selectors U+FE00–FE0F. Остальные управляющие и невидимые запрещены |
| То, что нельзя отвергнуть (имена из ELF) | При показе: `sanitize_for_display` заменяет опасные символы на видимые `\\u{..}` и удваивает `\\`. `Program::symbol_name` и тексты ошибок делают это сами, сырое имя остаётся в `LoadedImage::symbols` |

CLI пропускает прочие данные из файла (строки) через `sanitize_for_display` при текстовом выводе, UI — тоже: `Qt::PlainText` защищает от разметки, но не от bidi. В JSON-отчёте сырые поля загрузчика (`symbols[].name`, `strings[].value`) отдаются как есть, а отображаемые имена (`functions[].name`, текст операндов) — уже экранированные.

Эти правила применяются и при replay, поэтому после выпуска формата журнала их нельзя ужесточать без миграции: старые проекты перестанут открываться.

Ограничения размера (SEC-CORE-03/08): `MAX_BATCH_OPS`, `MAX_BATCH_DEPTH`, `MAX_PATCHED_BYTES`, `MAX_JOURNAL_ENTRIES`, `MAX_OPERATION_JSON_BYTES` (JSON операции и её обратной; хранилище обязано читать такой размер), `MAX_SEQ`, длина автора и id плагина. Бюджет `MAX_PATCHED_BYTES` действует на живые изменения и на конечное состояние replay; промежуточные состояния replay ограничены лишь `MAX_REPLAY_PATCHED_BYTES`, потому что scoped undo создаёт последовательности, которых в живой сессии не было. Ядро — единственный источник этих чисел. Формат журнала ещё не выпускался, поэтому `JOURNAL_FORMAT_VERSION` не менялась.

## Альтернативы

- **`RwLock<Program>`**: UI берёт read-lock. Отвергнуто: долгий writer (слияние результатов) блокирует UI, read-lock в UI-потоке противоречит принципу «ничего не блокирует».
- **`Arc` + полная копия коллекций (`BTreeMap`) на каждую публикацию**: просто, но O(n) на публикацию; при 100k функций и 10 публикациях/с — заметная нагрузка и всплески памяти. Персистентные мапы дают то же API при O(log n).
- **`im`** вместо `imbl`: `im` не обновлялся с 2022 г.; `imbl` — поддерживаемый форк с тем же API.
- **Undo через «перепроигрывание журнала без последней операции»**: просто, но O(N) на каждый Ctrl+Z и не даёт undo внутри функции. Отвергнуто в пользу хранимой обратной операции.
- **Хранить обратную операцию как «слепок» затронутых слотов** (generic key/value): гибче, но непрозрачно для истории и импорта. Выбрано «обратная — тоже `Operation`»: история читается людьми, та же сериализация.
- **Журнал в своём бинарном формате**: отвергнут дизайном (SQLite + WAL).

## Последствия

- Frontend может делать rename/Ctrl+Z с `testing::mock_session()` уже сейчас; Backend #3 реализует только `ProjectStore` (6 методов), вся логика undo уже в core и покрыта тестами.
- `Session::apply`/`undo`/`redo` применяют операцию к **копии** `Journal` и подменяют журнал только после успешной записи в store. Копия дешёвая: записи журнала лежат в персистентном `imbl::Vector`, `UserState` — в `imbl`-мапах, т.е. клон O(1), запись — O(log n). Выбрано вместо отката мутации (нужно точно восстанавливать состояния и обратные операции нескольких записей при undo/redo — источник ошибок) и вместо двухфазного prepare/commit (то же самое, но с новым публичным API). Замер (2026-11-07, синтетика, `InMemoryStore`): 10 000 `Session::apply` — 89 мс в release (≈ 9 мкс/операция), 0,44 с в debug; было 125 с в release из-за O(n)-клона. Регрессионный тест `ten_thousand_applies_are_fast` (бюджет: 1 с release, 10 с debug).
- Слушатели вызываются в потоке публикации и обязаны быть дешёвыми и неблокирующими (Qt-мост — через очередь событий Qt, ADR 0005).
- Формат JSON операций — часть формата проекта: изменения только добавлением, с миграциями в `dasm-db`.

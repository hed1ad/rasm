# ADR 0004. Формат JSON `dasm analyze --json`

Статус: предложено (этап 0) · 2026-11-07 · Architect

## Контекст

QA строит golden-тесты против `readelf`/`objdump`/`nm` и проверяет критерий «≥ 95 % функций из FDE `.eh_frame`, байты и длины инструкций совпадают с objdump». Нужен стабильный машиночитаемый контракт между CLI (Backend #3) и тестами (QA), который не дрейфует при рефакторинге внутренних типов.

## Решение

- Схема описана **Rust-типами** в `dasm_core::report` (`AnalyzeReport` и вложенные `*Report`), с `Serialize + Deserialize`. CLI строит отчёт одной функцией `AnalyzeReport::from_snapshot(&snapshot, &ReportOptions)` и печатает `serde_json`; тесты QA парсят вывод теми же типами. Документ для людей — `docs/api/analyze-json.md`.
- DTO-слой отделён от модели: внутренние типы (`Function`, `BasicBlock`...) могут меняться, отчёт — только по правилам версии.
- Адреса — строки `"0x401000"` (64-битные числа теряют точность в JS/`jq`); размеры, смещения в файле и счётчики — числа (< 2^53). Байты и SHA-256/build-id — нижний регистр hex без разделителей.
- Enum'ы — `snake_case` строки. Отсутствующее значение — `null` (поле присутствует), кроме `functions[].instructions`, которое есть только с `--insns`.
- Порядок детерминирован: сегменты/функции/строки по адресу, символы по (адрес, имя), xrefs по (from, to, kind) без дублей. Это позволяет диффать вывод в golden-тестах.
- Версионирование: `schema_version` (сейчас `1`). Добавление поля/варианта enum — без смены версии (клиенты обязаны игнорировать неизвестные поля). Удаление/переименование/смена смысла — `schema_version + 1` и запись в `analyze-json.md`.
- CLI: `dasm analyze <bin> [--json] [--insns] [--project file.dasm]`. Код возврата: 0 — успех; 1 — ошибка загрузки/анализа (сообщение в stderr, stdout пуст); 2 — неверные аргументы. Без `--json` — человекочитаемая сводка (не контракт).

## Альтернативы

- **JSON Schema-файл как источник правды + codegen**: лишний инструмент; Rust-типы + документ проще, а QA пишет тесты на Rust. JSON Schema можно сгенерировать позже (`schemars`), если появятся внешние потребители.
- **Сериализовать внутренние типы напрямую**: любой рефакторинг ломает QA. Отвергнуто.
- **Адреса числами**: короче, но ломается в JS и `jq` для адресов > 2^53 (kernel-адреса, тегированные указатели). Отвергнуто.
- **JSON Lines (по объекту на строку)**: удобно для стриминга огромных бинарей; пока не нужно, можно добавить `--jsonl` той же схемой элементов.

## Последствия

- QA может писать тесты сразу, используя `testing::mock_session()` + `AnalyzeReport::from_snapshot` (пример в `crates/dasm-core/src/testing.rs`, тест `report_roundtrips_through_json`).
- `--insns` на больших бинарях даёт десятки МБ — для golden-тестов используем небольшие фикстуры.
- Любая правка `dasm_core::report` проходит через Architect.

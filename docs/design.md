# Дизассемблер для Linux — дизайн-документ

Лицензия проекта: Apache-2.0. Имя бинаря и Python-модуля: `dasm`.

## Видение и цели

Linux-first инструмент реверс-инжиниринга с анализом уровня IDA и Ghidra, но с интерфейсом, в котором новичок за первый час находит main и размечает функции, а эксперт работает только с клавиатуры.

Для кого:
- Исследователи безопасности: малварь под Linux, IoT-прошивки, аудит закрытых библиотек.
- Участники CTF и студенты: IDA дорогая, Ghidra перегружена.
- Разработчики, которым надо понять бинарь без исходников.

| Инструмент | Берём | Исправляем |
|---|---|---|
| IDA Pro | Качество автоанализа, граф, xrefs, сигнатуры библиотек, клавиатурность | Цена, устаревший UI, модальные диалоги, неочевидные хоткеи |
| Ghidra | SLEIGH-описания архитектур, P-code, декомпилятор | Java/Swing, медленный старт, перегруженные окна |
| Binary Ninja | Многоуровневый IR, API-first | Закрытость, цена |
| Cutter / Rizin | Открытость, Qt-интерфейс | Слабее анализ и декомпиляция |

Принципы:
- **Linux-first.** ELF, DWARF, debuginfod, glibc и musl, бинарники Go и Rust поддерживаем лучше всех.
- **Ничего не блокирует.** Анализ идёт в фоне, работать можно с первой секунды.
- **Одна модель — много видов.** Псевдокод, граф, листинг и hex синхронизированы.
- **API-first.** Всё, что делает UI, доступно плагинам, скриптам и headless-режиму.
- **Обнаруживаемость.** Командная палитра, подсказки, пресеты хоткеев IDA и Ghidra.

Не цели первой версии: UI под Windows и macOS, PE и Mach-O как основные форматы (придут плагинами), собственный декомпилятор.

## Ключевые технические решения

| Область | Решение | Почему | Отвергнутая альтернатива |
|---|---|---|---|
| Ядро | Rust | Безопасный разбор недоверенных бинарей, параллелизм (rayon), крейты для ELF и DWARF | C++: выше риск уязвимостей в парсерах |
| UI | Qt 6 Widgets (C++) + Qt Advanced Docking System | Нативно в KDE/GNOME, Wayland, HiDPI; быстрые кастомные виды | GTK4, egui, Tauri |
| Связка Rust ↔ C++ | cxx и cxx-qt | Типобезопасный мост, модели Qt прямо из Rust | Ручной C ABI |
| Декодирование и семантика | SLEIGH-рантайм на Rust + iced-x86 для отображения x86 | SLEIGH даёт десятки архитектур с семантикой; iced — эталонный декодер x86 | Capstone — без семантики |
| IR | Собственный SSA IR в трёх уровнях | Один фундамент для анализа, плагинов и своего декомпилятора | Работать прямо на P-code |
| Декомпилятор v1 | Ghidra decompiler (C++, Apache 2.0) в отдельном процессе | Готовое качество; так сделано в rz-ghidra | Свой с нуля |
| Хранилище | SQLite + журнал операций | Атомарность, автосохранение, undo, основа совместной работы | Свой бинарный формат |
| Скрипты | Python 3 через PyO3 | Стандарт индустрии | Lua |
| Изоляция плагинов | WebAssembly (wasmtime) | Недоверенный код с явными разрешениями | Только нативные .so |
| Дистрибуция | Flatpak, AppImage, пакеты Arch, Debian, Fedora | Охват дистрибутивов | Только исходники |

Библиотеки: собственный парсер ELF с проверкой границ (решение 2026-11-07, вместо goblin), gimli (DWARF, .eh_frame), iced (x86), icicle-emu (SLEIGH-рантайм), cxx-qt, Qt Advanced Docking System, Ghidra (SLEIGH и декомпилятор), rz-ghidra (пример интеграции).

## Общая архитектура

Ядро — библиотека без UI; десктоп, CLI, Python и плагины работают с ним только через публичный API; всё, что может упасть или зависнуть, вынесено в отдельные процессы.

- Главный процесс: UI-поток Qt + пул потоков анализа (rayon). UI читает модель через снимки (snapshot) и никогда не ждёт анализ.
- Изменения модели идут только через операции: UI, скрипт и плагин вызывают одну и ту же `rename()`, она попадает в журнал и undo.
- Отдельные процессы: декомпилятор, бэкенд отладчика, WASM-песочница. IPC — Unix-сокет + бинарный протокол. Падение декомпилятора не роняет приложение, процесс перезапускается.
- Headless-режим — тот же бинарь без UI: `dasm analyze ./bin --script export.py`. Для CI, пакетной обработки, тестов плагинов.

## Ядро анализа

Анализ — граф проходов с явными зависимостями: инкрементальный (правка пересчитывает только зависимое), параллельный по функциям, в первую очередь обрабатывает то, что пользователь смотрит сейчас.

Конвейер:
1. Загрузка ELF: сегменты, секции, символы, релокации, PLT/GOT, TLS, build-id. PIE грузится по настраиваемой базе с возможностью rebase.
2. Отладочная информация: DWARF — имена, типы, локальные переменные; `.eh_frame` — границы функций даже в stripped; debuginfod по build-id.
3. Точки входа: entry, символы, FDE из `.eh_frame`, init_array/fini_array, указатели на код в данных.
4. Обход кода: рекурсивный спуск, затем линейный проход по неразмеченным участкам с эвристиками прологов.
5. CFG и функции: jump-таблицы через анализ значений на IR, tail call, noreturn-функции.
6. Лифтинг и SSA: распространение констант, стековые переменные, соглашения о вызовах (SysV AMD64, AAPCS64, RISC-V LP64).
7. Xrefs и данные: код→код и код→данные с типом доступа (чтение, запись, вызов), строки ASCII/UTF-8/UTF-16.
8. Идентификация библиотек: сигнатуры (аналог FLIRT) из .a; библиотеки типов glibc, musl, syscalls.
9. Языковые анализаторы: C++ (демангл, vtables, RTTI), Rust (демангл legacy и v0, &str, паники), Go (pclntab).

Уровни IR: LIR (по инструкции, явные регистры и флаги, близко к P-code; эмуляция) → MIR (SSA, стек разобран, флаги свёрнуты; data flow, плагины) → HIR (выражения, циклы, if/switch, типы; псевдокод, свой декомпилятор).

Декомпиляция: единый интерфейс `Decompiler`: на вход функция и типы, на выход дерево токенов, каждый токен привязан к адресам (синхронизация псевдокода и листинга). v1 — Ghidra в отдельном процессе; v2 — свой на HIR.

Архитектуры (полноценная поддержка по порядку): x86-64 → AArch64 → x86 → ARM/Thumb → RISC-V → MIPS.

## UI/UX

Всё находится через командную палитру, все виды синхронизированы, ни одно действие не открывает блокирующее окно.

| Вид | Что показывает | Особенности |
|---|---|---|
| Псевдокод | Декомпилированная функция | Переименование и смена типа в тексте, сворачивание блоков |
| Граф | CFG функции | Мини-карта, подсветка пути, цвета веток true/false |
| Линейный листинг | Весь бинарь | Виртуализированный скролл на миллионы строк, данные и код вперемешку |
| Hex | Байты | Наложение типов, патчинг |
| Граф вызовов | Кто кого вызывает | Фокус на функции ± N уровней |
| Строки, импорты, типы | Списки | Нечёткий поиск, сортировка, переход по Enter |

Навигация: палитра Ctrl+K (адрес, функция, строка, тип, команда; нечёткий поиск; рядом хоткей); история Alt+←/Alt+→ и недавние места; хлебные крошки файл › секция › функция › блок; карточки при наведении; полоса навигации по адресному пространству; вкладки и разделение видов.

Правка без трения: переименование по N или двойному клику на месте с превью использований; смена типа с автодополнением; комментарии, закладки, цветные теги; всё отменяется Ctrl+Z; анализ пересчитывается в фоне после каждой правки.

Помощь новичку: стартовые точки «Где main?», «Что импортирует бинарь?», «Подозрительные строки»; подсказка по мнемонике; пустые панели объясняют, что в них появится.

Настройка: пресеты хоткеев (свой, IDA, Ghidra); раскладки окон «Анализ», «Отладка», «Минимальная»; темы светлая, тёмная, высококонтрастная.

## Система плагинов

Встроенный ELF-загрузчик, x86 и связка с декомпилятором Ghidra сами оформлены как плагины на публичном API.

Точки расширения: Loader, Architecture, Analysis pass, Decompiler, View/Panel, Command, Annotator, Debugger backend, Type library/Signatures, Theme/Keymap.

Три уровня API: нативный (Rust/C/C++ .so через стабильный C ABI), скриптовый (Python 3), песочница (WASM через wasmtime, доступ по разрешениям). Одно описание API (IDL) → C-заголовки, Rust/C++-обёртки, Python-модуль, .pyi. Версионирование api = major.minor.

Манифест:
```toml
[plugin]
id = "com.example.crypto-finder"
name = "Crypto Finder"
version = "1.2.0"
api = "1.0"
kind = "python"        # native | python | wasm
entry = "main.py"

[activation]
on = ["binary_opened", "command:crypto.scan"]

[provides]
analysis_passes = ["crypto_constants"]
commands = ["crypto.scan"]
panels = ["crypto.results"]

[permissions]
network = false
filesystem = ["project"]
```

Пример плагина:
```python
import dasm

@dasm.analysis_pass(name="crypto_constants", after=["functions"])
def find_crypto(ctx: dasm.AnalysisContext):
    for fn in ctx.program.functions:
        for insn in fn.instructions():
            if insn.has_immediate(0x67452301):  # MD5/SHA-1 init
                ctx.tag(insn.address, "crypto", "MD5/SHA-1 init")

@dasm.command("crypto.scan", title="Найти криптоконстанты", shortcut="Ctrl+Alt+C")
def scan(app: dasm.App):
    app.analysis.run("crypto_constants", scope=app.current_function)
```

Жизненный цикл: обнаружение → проверка (api, подписи, разрешения) → регистрация (код не выполняется) → ленивая активация по событию → выгрузка. События: binary_opened, analysis_finished, function_added, symbol_renamed, type_changed, cursor_moved, selection_changed. Плагин меняет модель только через операции.

## Модель данных проекта

Проект — один файл SQLite; журнал пользовательских операций — единственный источник правды, результаты анализа — пересчитываемый кэш.

Слои снизу вверх: исходные байты (копия или ссылка + SHA-256) → патчи байтов → журнал операций → результаты анализа (кэш).

Операции: rename, set_type, comment, define_code, define_data, create_function, delete_function, patch_bytes, bookmark, tag. Каждая обратима, хранит автора, время и источник (UI, скрипт, плагин). Undo/redo глобальный и в пределах функции. Автосохранение в режиме WAL. Экспорт: патченный ELF, .h, символы для GDB, JSON. Импорт из IDA и Ghidra. Совместная работа — позже.
